## 확정 원인 / 가능성 높은 원인 / 미확인

- **확정**: 분석은 호출됐고, 기사마다 AI 호출 단계에서 예외가 나 `pending`으로 되돌아갔다. 분석 경로가 이 실패를 HTTP 200
  `{ analyzed: 0, errors: [...] }`로 돌려주고, `collect`는 `!ar.ok`일 때만 알림을 보내므로 **실패가 성공처럼 처리되어 알림이 없었다**.
- **확정(부차 버그)**: 실패한 기사는 같은 `created_at`으로 `pending`에 돌아가 다음 호출에서 또 뽑힌다. 한 실행 안에서 **같은 3건만 반복**
  시도하고 나머지 72건은 시도조차 되지 않는다(하루 3건만 `updated_at` 갱신).
- **가능성 높음**: 운영 `GEMINI_API_KEY`로 하는 Gemini 호출 자체가 실패(할당량·결제·키 제한/교체). 세 개의 독립 Gemini 작업이 동시에
  결과가 없고, 10/25 아침(이번 코드 변경 전)에도 같았기 때문이다.
- **미확인**: 실제 오류 메시지(429/403/400 등). Vercel Hobby는 실행 로그를 약 1시간만 보관해 오전 로그가 없다. 운영 키 값은 조회하지
  않았다(민감 정보). 10/26 07:30 뉴스레터 실패 알림 메일에 실제 오류가 들어 있을 수 있다(`뉴스레터 cron 실패 — 초안 생성`).

## 수정 계획 (별도 승인 후 구현)

1. **실패를 실패로**: `analyze-pending`이 `{ attempted, analyzed, failed, errors[] }`를 돌려주고, 시도한 기사가 모두 실패하면 HTTP 502.
   오류는 공급자·HTTP 상태·요약만(키·프롬프트 제외).
2. **알림**: `collect`가 `failed > 0 && analyzed == 0`이면 `sendAdminAlert("기사 분석 실패", 오류 요약)`. 같은 날 중복 알림은 1회.
3. **같은 기사 반복 방지**: 한 실행 안에서 시도한 기사 ID를 넘겨 제외(`exclude` 파라미터) — 스키마 변경 없음. 이후 필요하면
   `analysis_attempts`·`last_analysis_error` 열 추가(마이그레이션, 별도 승인).
4. **AI 호출 시간 제한**: Gemini `fetch`에 `AbortSignal.timeout(60_000)`. 공급자 실패 사유(할당량/키/결제)를 오류에 남김.
5. **상태 확인**: "원문 7일 이내 pending이 있는데 24시간 동안 새 insight 0건"이면 관리자 알림(다음 날 08:00 드립 전에 감지).
6. 뉴스레터·퀴즈도 같은 오류 요약 형식 사용.
7. 테스트: 공급자 오류 모의 → 502·알림·반복 제외·키 비노출 검증. 유료 호출 없이 모의 응답만 사용.
