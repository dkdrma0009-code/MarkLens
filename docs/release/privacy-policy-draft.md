### R-4에서 코드로 다시 확인한 사실 (2026-10-25)

- 메일: `marklens.site`에 **MX 레코드가 없다** — `newsletter@marklens.site`는 발신 전용(Brevo 인증 TXT·DMARC만). 회신·문의를 받으려면 다른 주소가 필요하다. 관리자 알림을 받는 기존 `naver.com` 주소(`ADMIN_EMAIL`)가 있다.
- 처리 위치: Supabase 운영 DB **서울**(AWS ap-northeast-2), Vercel 서버 함수 **미국 iad1**(페이지 캐시는 서울 등), Brevo 메일 발송(트랜잭션 발송만, 연락처 목록 없음), Google Analytics 4(`G-9NCMJC4V6L`, 운영 공개 페이지에서만, 관리자·로그인 제외, 동의 배너 없음), AI는 Gemini → Claude → OpenAI 순서의 대체 경로.
- 뉴스레터 발송·열람·클릭 기록(`newsletter_events`, 이메일 포함)이 Brevo 웹훅으로 쌓인다 — 처리방침 항목과 삭제 SQL에 포함했다.
- 운영 DB 점검(읽기 전용, 건수만): Insight Lab은 **운영에서 이미 저장 중**(로그인 계정 1, 세션 1, 통계 1, 노트 0). 구독자 active 9·pending 2·해지 0. `ai_usage`는 아직 없다(024 미적용) — 새 코드 배포와 함께 생긴다.

- 구독 해지(`/api/unsubscribe`)는 `status=unsubscribed`, `unsubscribed_at` 기록뿐이다. **구독자 행을 지우는 경로는 앱에 없다** — 운영자 SQL 절차로 지운다([privacy-operations.md](privacy-operations.md)).
- Insight Lab 계정 삭제 경로가 앱에 없다(관리자 대시보드에서만 가능). 계정이 지워지면 세션·노트·통계는 `ON DELETE CASCADE`로 함께 지워진다.
- AI 입력: 챗·면접 연습·학습 채점은 AI 제공사로 보내기만 하고 DB에 저장하지 않는다. Insight Lab 답변(`insight_sessions`, 직접 입력한 기사 본문 포함)은 저장된다.
- AI 사용량 기록(`ai_usage`, IP 해시·회원 id)은 앱의 정리 작업이 없다 — 운영자 정기 파기 SQL **[C]** 로 기간이 지난 행을 지운다.
- 인사이트 피드백 코멘트는 관리자 알림 메일로 Brevo를 거쳐 전송된다.
- `analytics_events` 테이블은 쓰는 코드가 없다(수집 없음).
- Insight Lab 로그인 메일(매직 링크)은 Supabase Auth가 보낸다.

## A. 구독 폼 고지 UI 초안

적용 위치는 두 곳이다. 둘 다 폼 아래에 있는 기존 안내 문단 바로 다음에 한 줄을 추가한다.
- `src/components/NewsletterInlineCta.tsx`(홈·상세 하단 등)
- `src/app/(public)/newsletter/NewsletterClient.tsx`(`#weekly-note`)

표시 원칙:
- 기존 `ml-form-note` 스타일(12px 이상)을 재사용하고 본문 대비 4.5:1 이상으로 한다.
- 레이아웃·버튼·입력창은 그대로 둔다(디자인 변경 없음).

**A-1. 광고성 정보 동의가 필요 없다는 검토 결과일 때 — 안내 한 줄**

```
이메일 주소는 MarkLens 뉴스레터 발송에만 쓰며, 구독을 해지하면 [보유 기간 — 운영자 확인 필요] 안에 파기합니다. 자세한 내용은 개인정보처리방침에서 확인할 수 있습니다.
```
- "개인정보처리방침"은 `/privacy` 링크다.
- 입력창의 `aria-describedby`에 이 문단 id를 추가한다(스크린리더가 함께 읽도록).

**A-2. 별도 동의가 필요하다는 검토 결과일 때 — 체크박스** `[법률 검토 필요]`

```
[ ] (필수) 개인정보 수집·이용에 동의합니다 — 항목: 이메일 / 목적: 뉴스레터 발송 / 보유: 해지 후 [기간]  [자세히]
[ ] (필수 또는 선택 — 검토 결과) 광고성 정보 수신에 동의합니다
```
- 필수 항목에 체크하지 않으면 제출 버튼을 비활성화하고, 그 이유를 버튼 아래에 문장으로 보여준다.
- 동의 시각을 저장하려면 `subscribers`에 컬럼을 추가해야 한다(별도 마이그레이션 — 이번 범위 아님). 구독 API 계약(`email`, `source`)은 유지하고 필드만 추가한다.
- 광고성 정보에 해당하면 메일 제목의 `(광고)` 표기와 야간(21시–8시) 발송 제한을 검토한다. 현재 발송 시각은 월요일 7:30이므로 해당 여부 확인이 필요하다 `[법률 검토 필요]`.

## C. 결정 후 필요한 코드 변경 (이번 범위 아님)

1. **해지 시 처리:** 결정한 보유 기간에 맞춰 바꾼다.
   - 현재 `/api/unsubscribe`는 `status=unsubscribed`만 기록한다.
   - 즉시 삭제로 정하면 행을 지운다(재구독 시 새 행).
   - 기간 후 파기로 정하면 정기 삭제 작업을 추가한다.
2. **`/privacy` 페이지와 연결:** B를 확정한 뒤 `/privacy` 페이지를 만들고, 푸터와 두 구독 폼에 링크를 단다.
3. **동의 시각 저장:** A-2를 채택하면 `subscribers`에 동의 시각 컬럼을 추가하는 마이그레이션과 API 필드를 추가한다.
4. **AI 입력 저장 여부 재확인:** 경로별(면접 리포트, Insight Lab 평가)로 입력 원문이 DB에 남는지 확인해 1항을 확정한다. Insight Lab은 답변을 `insight_sessions`에 저장한다.
