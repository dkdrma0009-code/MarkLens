# 운영자 직접 확인 절차 (P9E)

운영자만 볼 수 있는 화면의 확인 절차다. API 키, DB 비밀번호, 서비스 키는 어디에도 붙여 넣거나 공유하지 않는다. 결과만 공유한다.

## 1. Gemini 요금 등급 (약 5분)

**왜 필요한가:** [Gemini API 약관](https://aistudio.google.com/docs/terms)상 입력이 학습에 쓰이지 않는 것은 활성 결제 계정이 연결된 Cloud 프로젝트로 호출할 때뿐이다. 무료 사용분은 입력이 제품·모델 개선에 쓰이고 사람이 검토할 수 있으며, 약관은 개인정보를 넣지 말라고 안내한다. 확인 전에는 "학습에 쓰지 않는다"고 안내할 수 없다.

| # | 어디서 | 확인할 것 | 기록 |
|---|---|---|---|
| 1 | [API keys](https://aistudio.google.com/api-keys) | 키 목록, 각 키의 프로젝트, Plan 표시 | 프로젝트 이름, Plan |
| 2 | [Projects](https://aistudio.google.com/projects) | 그 프로젝트의 Billing Tier 열. 목록에 없으면 Import projects | Free / Tier 1·2·3 |
| 3 | [Billing](https://aistudio.google.com/billing) | "Set up billing"이 보이면 결제 계정 없음, "No credits"면 잔액 소진 | 활성 결제 계정 있음 / 없음 |
| 4 | [Usage](https://aistudio.google.com/usage) | 어떤 키에 사용량이 있었는지 (아래) | 실제 사용 키의 이름 |

**실제 운영 키 찾기:** Vercel의 `GEMINI_API_KEY`는 Secret이라 값을 다시 볼 수 없고, 저장소로도 어느 키인지 알 수 없다.
- 키나 Gemini 프로젝트가 하나뿐이면 그것이 운영 키다.
- 여러 개면 Usage 화면에서 프로젝트와 키별 사용량을 보고, **AI를 멈춘 2026-11-01 이전까지 꾸준히 사용되다 그 뒤 끊긴 키**를 찾는다.
- 그래도 구분되지 않으면 **유료로 확인하지 못한 것으로 처리한다.** AI를 다시 켤 때 유료 프로젝트에 새 키를 만들어 교체한다.

**결과별 조치:**

| 결과 | 조치 |
|---|---|
| 해당 프로젝트 Tier 1 이상, 활성 결제 계정 있음 | `geminiPaidConfirmed`를 `true`로 변경 가능 |
| Free 또는 결제 계정 없음 | `false` 유지. AI를 다시 켜기 전에 결제 프로젝트로 전환. 개정 방침의 학습 미사용 문구 공개 불가 |
| 실제 키를 특정하지 못함 | `false` 유지 |

**문서에서 확인한 조건:** 유료는 입력·응답을 제품 개선에 쓰지 않지만, 금지 사용 탐지를 위해 제한된 기간 기록한다. [사용 정책](https://aistudio.google.com/docs/usage-policies)의 기록 보관은 55일이고 등급별 구분은 적혀 있지 않다. 등급은 [결제 계정 단위](https://aistudio.google.com/docs/billing)로 정해진다.

**AI를 다시 켤 때 참고:** 제한 없는 키가 오래 쓰이지 않으면 Google이 차단할 수 있다고 안내하므로, AI를 켜기 전에 API keys 화면에서 Blocked 표시를 확인한다.

## 2. 운영 퀴즈 수량 (약 3분)

**SQL 파일:** `docs/release/p9d-quiz-db-check.sql`. SELECT 한 문장이고 문제 본문은 돌려주지 않는다.

1. Supabase Dashboard에서 **운영 프로젝트**(ref `ndehtnchkgvpjbxlkazk`)를 연다.
2. SQL Editor → New query에 파일 전체를 붙여 넣는다. 파일 외의 내용을 추가하지 않는다.
3. Run을 한 번 누른다. 경고가 뜨면 실행하지 말고 알려 준다.
4. 결과 표를 공유한다(CSV나 캡처). 수량과 날짜만 들어 있다.

| 열 | 뜻 |
|---|---|
| `level`, `type` | 난이도, 문제 유형. 표에 난이도별 객관식·단답형 6줄이 나오며, 문제가 없어도 0으로 표시된다 |
| `total` | 저장된 행 수 |
| `usable_ai_off` | **AI가 꺼진 동안 실제로 낼 수 있는 객관식 수.** 형식이 유효하고 유사문제를 뺀 수 |
| `type_mismatch` | `type` 열과 문제 내부 유형이 다른 행 수 |
| `invalid_choices` | 보기나 정답 형식이 잘못된 객관식 행 수 |
| `oldest`, `newest` | 가장 오래된·최근 문제의 날짜 |
| `verdict` | 객관식 줄의 판정 |
| `random_quiz_exists` | 앱이 쓰는 조회 함수의 존재 여부. `false`면 퀴즈가 동작하지 않는다 |

| 판정 | 뜻 | 조치 |
|---|---|---|
| 세 난이도 모두 `정상` (10개 이상) | 기본 10문제 제공 가능. 20문제는 부족 안내가 나올 수 있다 | 진행 |
| `부족` (1~9개) | 해당 난이도는 있는 만큼만 나오고 안내가 표시된다 | 그대로 출시할지, 문제를 보충할지 결정 |
| `0개` | 해당 난이도는 "제공할 문제 없음"만 나온다 | 보충 전에는 그 난이도 또는 퀴즈를 출시 범위에서 제외 |
| `type_mismatch`나 `invalid_choices`가 0이 아님 | 일부 문제가 빠지거나 표시 오류 가능 | 수량을 공유해 원인 확인 |
| 실행 오류 | 운영 스키마가 저장소 기록과 다름 | 오류 문구만 공유 |

AI가 멈춘 동안에는 주간 자동 생성이 건너뛰어 문제가 지워지지 않지만 새로 채워지지도 않는다. 보충(유료 AI 생성 또는 검수 문제 입력)은 별도 승인을 받는다.
